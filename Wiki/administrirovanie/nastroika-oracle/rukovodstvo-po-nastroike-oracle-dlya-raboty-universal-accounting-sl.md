# Руководство по настройке Oracle для работы Universal Accounting SL

Руководство по настройке Oracle для работы Universal Accounting SL

В тексте инструкции встречаются переменные username, fromuser — вместо username мысленно подставляете имя пользователя, которого хотите создать (например un4, baurghi, aermur). Вместо fromuser мысленно подставляете имя пользователя, из которого был сделан экспорт (например un4, fsr, mtc) — необходимо уточнить это имя у человека, который дал вам базу. В крайнем случае посмотреть это имя можно, открыв файл .DMP в Far по F3 — имя пользователя может быть после connect, например (connect un4). Последние версии скриптов user\_UN4public.sql, user\_UN4pack.sql можно взять из GOOD'а.

{% stepper %}
{% step %}
### Подготовка и создание табличных пространств

1. Создать папку ORADATA.un4 в директории oracle.
2. Запустить TOAD, подключиться пользователем sys с паролем sys.
3. Открыть файл sys\_Tablespaces.sql.
4. В каждом из табличных пространств поменять путь на необходимый.
5. Выполнить скрипт по клавише F5 (проходит долго, не пугаться).
{% endstep %}

{% step %}
### Установка публичных объектов пользователя

1. Открыть файл user\_UN4public.sql.
2. При выполнении, если при операции DROP каких-то объектов не существует — нажимать Continue Script.
3. Если ошибки возникают при создании каких-то объектов, то операция считается неудачной — надо разобраться в причинах, исправить их и повторить выполнение скрипта.
{% endstep %}

{% step %}
### (Опционально) Упаковка INI-данных, дизайнов и пр.

Если требуется возможность работы в режиме упаковки INI-данных, дизайнов и пр. (обычно это нужно при работе удаленных клиентов), то выполнить пункты установки публичных объектов для файла user\_UN4pack.sql (т.е. открыть user\_UN4pack.sql и выполнить аналогично).
{% endstep %}

{% step %}
### Создать схему пользователя

См. раздел "Создание пользователя" ниже.
{% endstep %}

{% step %}
### Запуск программ и проверка входа

1. Попробовать запустить программу Administrator.exe (Ctrl+F12).
   * Если вход не получается — разобраться в причинах и исправить их.
2. Попробовать запустить программу uniacCLNT.exe (Ctrl+F12).
   * Если вход не получается — разобраться в причинах и исправить их.
{% endstep %}

{% step %}
### Ошибка ORA-28100

Если возникает ошибка "ORA-28100: Policy function schema string is invalid" (или по-русски "ORA-28100: Неверная функциональная схема методики"), нужно удалить все методики пользователя. Для этого, например, подключиться в TOAD под sys и открыть Schema Browser, в выпадающем справочнике в левом верхнем углу выбрать пользователя "username", открыть вкладку Policies и удалить все Policies.
{% endstep %}
{% endstepper %}

***

Создание пользователя

Ниже приведены два варианта — (a) подходит для первой и последующих схем пользователя; (b) подходит только для первой схемы пользователя.

{% stepper %}
{% step %}
### Вариант a) Импорт через run.bat (для первой и последующих схем)

1.  Открыть папку Import. Найти файл run.bat и открыть (в Проводнике правой кнопкой — "Изменить").\
    Команда внутри:\
    imp1 oraservice fromuser username

    * imp1 — имя файла который будет вызван (не менять).
    * oraservice — имя службы oracle на которую мы хотим сделать импорт.
    * fromuser, username — описаны в начале файла (см. переменные в начале инструкции).

    Например:

    ```
    imp1 ora1 un4 prim
    ```

    Также необходимо настроить правильные пароли в файле imp1.bat:

    ```
    sqlplus sys/sys  (user / password)
    IMP system/sys
    ```
2. Скопировать в папку Import файл Expdat.dmp; если он называется иначе — переименуйте.
3. Запустить run.bat.
   * В случае, если на экране появляются предложения ввести user и password — проверяйте в imp1: sqlplus sys/sys (user/password) и IMP system/sys — правильность пароля.
4. Log file implog.log будет в той же папке Import — в нем необходимо анализировать сообщения.
{% endstep %}

{% step %}
### Вариант b) Через user.sql и Import Utility Wizard (только для первой схемы)

1. Открыть в TOAD файл user.sql из папки Import.
   * Заменить username на имя пользователя, которое мы хотим создать.
   * Выполнить скрипт (клавишей F5).
   * Если при операции DROP каких-то объектов не существует — нажимать Continue Script.\
     (Будет создан пользователь username.)
2. В TOAD -> DBA -> Import Utility Wizard -> Import Users:
   * Указать from user "fromuser" to user "username".
   * Export File Name указать файл expdat.dmp. Log file по умолчанию будет по тому же пути, что expdat.dmp.
{% endstep %}
{% endstepper %}

{% hint style="danger" %}
После импорта любым способом — проанализировать log file (анализировать можно, давая поиск по "ora-")!!!
{% endhint %}
