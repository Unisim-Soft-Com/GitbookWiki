# un$sld.make ORA-14450

{% stepper %}
{% step %}
### Если вызываем Un$sld.Make в пределах одной сессии и одной транзакции

Если вызвать Un$sld.Make в пределах одной сессии и одной транзакции, не передавая параметр pTableName (т.е. без id в таблице xsld), иногда может возникать ошибка блокировки.
{% endstep %}

{% step %}
### Если используем в гридах Prepare SQL

Prepare Sql блокирует xsld в основной сессии.

![Prepare SQL блокирует xsld в основной сессии](<../../../.gitbook/assets/image (190)>)

В противном случае последующие изменения xsld в автономных транзакциях (т.е. в экшенах) приводят к ошибке блокировки xsld.

Например, в проводках документа:

{% code title="Пример процедуры" %}
```plsql
procedure ship_inv_tax_gfc(p_nrdoc number) is
  v_valuta varchar2(3 byte);
 begin
  delete from vmdb_cmi where nrdoc=p_nrdoc;
  delete from xsld where id='ship_inv_tax_gfc';
  un$sld.make(nvl(abm_util.data_by_nrdoc(p_nrdoc),sysdate),'ship_inv_tax_gfc','ACDE12','2131');
```
{% endcode %}

![Ошибка блокировки при использовании в проводках документа](<../../../.gitbook/assets/image (191)>)
{% endstep %}

{% step %}
### Конфликт доступа к xsld в экшенах (автономная транзакция)

Также возникает конфликт доступа к xsld в экшенах (автономная транз.) с остатками после построения отчетов в УО.

Автономные транзакции вызываются Уной в экшенах, гридах.
{% endstep %}
{% endstepper %}

{% hint style="info" %}
Для устранения ошибки необходимо в каждой транзакции текущей сессии выполнять COMMIT.
{% endhint %}

{% hint style="info" %}
Второй вариант решения проблемы — использовать другую временную таблицу при подсчете остатков (вместо xsld).

Была доработана функция un$sld.make: добавлен параметр p\_cTable — имя таблицы для накопления остатков. Для избежания конфликта доступа к таблице xsld из автономной транзакции можно вызывать остатки с другим именем таблицы (например XSLD\_SHIP — для отгрузки).

Структура новой таблицы должна быть идентична xsld.
{% endhint %}
