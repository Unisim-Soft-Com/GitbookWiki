# Инструкция по прыжкам

#### Прыжки из документа

Открываем дизайн первого грида

![](<../.gitbook/assets/image (889)>)

С помощью горячих клавиш Alt+D, нажимаем и копируем:

```
DblClick=goto
TargetType=doc.print
NrDoc=_NRDOC
TargetSection=6:5:PRINTDOC_AKTRAZDELKI
GotoNextRecord=1
```

Сохраняем изменения и подтверждаем.

![](<../.gitbook/assets/image (890)>)

После двойного клика по любой строке колонки CANT2 (Возвращено) построится печатная форма данного документа.

![](<../.gitbook/assets/image (891)>)

После закрытия печатной формы произойдёт переход на другую строку (GotoNextRecord).

![](<../.gitbook/assets/image (892)>)

После двойного клика мыши построится печатная форма с другими данными (\_NRDOC).

![](<../.gitbook/assets/image (893)>)

(Повторяются аналогичные действия и результаты при иных двойных кликах — смена \_NRDOC и переходы по GotoNextRecord.)

Открываем дизайн другого грида, нажимаем Alt+D и записываем:

```
DblClick=goto
TargetType=doc.action
Action_ID=4
```

Сохраняем — в результате двойного клика по любой строке поля CANT3 (Возвращено) выполнится действие с ID=4 (например, «заполнить на основании списания ГП»).

![](<../.gitbook/assets/image (894)>)

Далее — другие примеры настройки DblClick в дизайне грида:

*   Открыть форму по двойному клику:

    ```
    DblClick=goto
    TargetType=form
    TargetSection=CURS
    ```

    В результате двойного клика по полю CANT3 откроется форма (например «Валютные курсы»).
*   Открыть карточку:

    ```
    DblClick=goto
    TargetType=cartela
    TargetSection=ATTR_ORD_ADD
    nrdoc=_nrdoc
    MainTA=1
    ```
*   Построить отчёт:

    ```
    DblClick=goto
    TargetType=report
    TargetSection=1:0:RG113
    ```

Имя секции можно посмотреть в конфигураторе, нажав кнопку Node properties — пример: rg113.

#### Прыжки из форм

Открываем любую форму (например «Валютные курсы»). Выделяем любое поле, открываем дизайн грида (Alt+D) и записываем:

```
DblClick=goto
TargetType=document
nrdoc=5645
```

Сохраняем изменения. В результате двойного клика по любой строке поля COD1 (Код1) происходит переход в документ с NrDoc=5645.

Если добавить свойство gotodocumentediting для пользователя или группы, документ после перехода откроется на редактирование. Сохраняем транзакцию (Commit), обновляем настройки в программе (F5) и подтверждаем обновление — далее двойной клик приведёт к открытию документа в режиме редактирования.

Также можно настроить возврат в форму после закрытия документа:

```
DblClick=goto
TargetType=document
nrdoc=5645
ReturnType=Form
ReturnSection=CURS
```

В результате переход в документ произойдёт, а после нажатия Сохранить/Отмена/Выход (или горячих сочетаний) — возврат в указанную секцию формы (CURS).

Другой пример — построение печатной формы из формы по двойному клику:

```
DblClick=goto
TargetType=form.print
TargetSection=0:0:PRINTFORM:SCALESEXP
```

Результат — построение печатной формы (имя секции печатной формы можно посмотреть через Node properties: например PRINTFORM).

Примеры создания нового документа и карточки из формы:

*   Создание нового документа:

    ```
    DblClick=goto
    TargetType=doc.new
    TargetSysFID=1400
    TargetJournal=MATERIALE
    ```

    В результате двойного клика создаётся новый документ с указанным SysFID.
*   Создание дочернего документа на основании: В конфигураторе у документа, у которого будут дочерние документы, добавляем свойство childdocs (значение — DB ID дочернего документа). Можно также добавить childcancelonerror (чтобы при ошибке вставка в tmdb\_docs отменялась). Сохраняем транзакцию и обновляем настройки (F5).

    В дизайне грида:

    ```
    DblClick=goto
    TargetType=doc.child
    ```

    При двойном клике будет создан дочерний документ (появится окно создания на основании, выбор даты и т.д.), затем он станет виден в журнале операций.

Можно включить автоматическое создание дочернего документа без запроса (silent):

* Добавить свойство createchildsilent у документа — тогда окно о создании на основании игнорируется и сразу открывается окно с настройкой даты документа.

#### Прыжки из отчётов

В конфигураторе открываем нужный журнал и добавляем свойство showreportsection, сохраняем транзакцию и обновляем настройки (F5). При открытии журнала будет строиться отчёт.

Имя секции отчёта можно посмотреть через Node properties при выделенном отчёте (например rg113).

Чтобы настроить переходы из построенного отчёта, открываем шаблон отчёта и в нужной строке (в колонке A обычно ставим служебное слово, например "title") в колонку F записываем команды вида:

*   Переход в форму:

    ```
    [RepJump]
    TargetType=form
    TargetSection=CURS
    ```

    В отчёте: первые три колонки (A,B,C) шаблона задают параметры; видимые колонки строящегося отчёта начинаются с D. Поэтому запись в колонке F шаблона соответствует колонке C в отчёте. При двойном клике мыши по соответствующей ячейке отчёта произойдёт переход в форму.

    В шаблоне можно также форматировать ячейки (правый клик → Format cells → Patterns / Fill color / Fill pattern), затем пересобрать отчёт — выбранная ячейка будет подсвечена, но при двойном клике переход сохраняется.
*   Переход в документ:

    ```
    [RepJump]
    TargetType=document
    nrdoc=5648
    ```

    При двойном клике по ячейке отчёта откроется указанный документ (если у пользователя установлено gotodocumentediting=true — документ откроется для редактирования).
*   Переход на отчёт:

    ```
    [RepJump]
    TargetType=report
    TargetSection=100:0:RPT:SLR_RG12
    ```

    При двойном клике левой кнопкой мыши — построится другой отчёт.
*   Создание нового документа:

    ```
    [RepJump]
    TargetType=doc.new
    TargetSysFID=1400
    TargetJournal=MATERIALE
    ```

    При двойном клике — создаётся новый документ с заданным SysFID; затем можно настроить childdocs и childcancelonerror у родительского документа, чтобы допускать создание дочерних документов из отчёта.
*   Создание дочернего документа из отчёта:

    ```
    [RepJump]
    TargetType=doc.child
    ```

    При двойном клике выйдет окно о создании документа на основании (или сразу окно выбора даты при установленном createchildsilent).

После внесения изменений в шаблоны/конфигурации не забудьте сохранить шаблон и обновить отчет (кнопка обновления) или перестроить отчет.

***

#### Примечание

*   Если в Header документа добавить кнопку (Button1) и в свойстве Params написать:

    ```
    TargetType=doc.child
    ```

    то при нажатии на неё выйдет сообщение о завершении операции редактирования документа. Это происходит из-за того, что документ находится в открытой незавершённой транзакции, которую необходимо завершить (Commit) или отменить (Rollback). Таким образом создание дочернего документа из открытого документа через кнопку в заголовке будет недоступно.
* Аналогично, если из открытого документа настроить в дизайне грида DblClick, который создаёт doc.child или doc.new, то при двойном клике также появится сообщение о необходимости завершить транзакцию (и создание будет невозможно).

Итого:

* Для корректной работы создания новых/дочерних документов из форм и отчетов необходимо, при необходимости, завершать текущие транзакции (Commit/Rollback) или использовать сценарии, которые не требуют открытой активной транзакции в исходном документе.
* Всегда сохраняйте изменения в конфигураторе (галочка Commit), обновляйте настройки клиентского приложения (F5) и проверяйте имена секций через Node properties, чтобы правильно указать TargetSection в переходах.
